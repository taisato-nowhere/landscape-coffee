# LANDSCAPE COFFEE 採用管理システム 要件定義ドラフト

最終更新: 2026-06-22 / ステータス: 構想整理

---

## 1. 背景・目的

LANDSCAPE COFFEE の店舗展開に合わせて、スタッフ採用を継続的に行える状態をつくる。応募経路が公式サイト、Indeed、スタンバイ、SNS、紹介、店頭などに分散すると、応募者対応の漏れや二重対応が起きやすい。

本システムでは、応募者情報をひとつの管理画面に集約し、応募受付から面接、評価、採用判断までを見える化する。

目的:
- 公式サイトから直接応募できる採用導線を用意する。
- Indeed やスタンバイなどの外部採用媒体から来た応募者も一元管理する。
- 応募者への連絡漏れ、面接調整漏れ、担当者間の認識ズレを防ぐ。
- 店舗別・職種別に採用状況を把握できるようにする。
- LANDSCAPE のブランドトーンに合った採用体験をつくる。

---

## 2. 位置づけ

既存の公式サイト v1 では採用ページはスコープ外だが、店舗展開に直結するため、v1直後のファストフォローまたは別アプリとして検討する。

推奨する分け方:
- 公式サイト側: 採用ページ、募集要項、応募フォーム、プライバシー同意。
- 採用管理側: 応募者一覧、ステータス管理、面接管理、評価、通知、CSV取込。

最初からすべての媒体API連携を前提にせず、公式サイト応募とCSV/メール取り込みをMVPにする。外部媒体の正式API連携は、媒体側の契約・審査・仕様確認後に追加する。

---

## 3. 対象ユーザー

| ユーザー | 主な利用目的 |
|---|---|
| 採用責任者 | 全応募者の確認、選考状況管理、採用判断 |
| 店舗責任者 | 担当店舗の応募者確認、面接メモ、評価 |
| 面接担当者 | 面接予定確認、評価入力 |
| 管理者 | ユーザー権限、募集職種、店舗、通知設定の管理 |

---

## 4. 応募流入元

| 流入元 | 初期対応 | 将来対応 |
|---|---|---|
| LANDSCAPE 公式サイト | 採用フォームから直接DB保存 | 募集職種ごとのLP最適化 |
| Indeed | CSV取込または応募通知メール取り込み | Indeed Apply / ATS連携を検討 |
| スタンバイ | CSV取込または応募通知メール取り込み | 公式連携可否を確認 |
| Instagram DM | 手動登録 | DM対応ルール整備 |
| 紹介 | 手動登録 | 紹介者フィールド追加 |
| 店頭応募 | 手動登録 | QRコード応募フォーム |

補足:
- Indeed は Indeed Apply により応募情報を外部システムへ送信する仕組みがあるが、利用には媒体側の条件や設定が必要。
- スタンバイは公開API前提にせず、初期はCSV/メール/手動登録で吸収する。
- 外部媒体の管理画面にログインして取り出す作業が残る場合でも、最終的な応募者台帳は本システムに寄せる。

最初に作るもの:

2. 募集要項一覧
3. 募集詳細
4. 応募フォーム

10. ステータス変更

- 労務契約、入社手続き、給与管理

## 6. 画面要件

### 6.1 採用トップ

パス候補:
- `/recruit`
- `/careers`

役割:
- LANDSCAPEで働く魅力を伝える。
- 店舗・職種ごとの募集へ誘導する。
- 応募前の不安を減らす。

掲載要素:
- 採用メッセージ
- 働く場所としてのLANDSCAPE
- 募集店舗
- 募集職種
- よくある質問
- 応募導線

### 6.2 募集要項一覧

パス候補:
- `/recruit/jobs`

表示項目:
- 職種
- 店舗
- 雇用形態
- 勤務地
- 募集状態
- 詳細リンク

### 6.3 募集詳細

パス候補:
- `/recruit/jobs/[slug]`

表示項目:
- 職種名
- 店舗
- 雇用形態
- 業務内容
- 勤務時間
- 給与
- 休日
- 応募条件
- 歓迎条件
- 選考フロー
- 応募ボタン

### 6.4 応募フォーム

パス候補:
- `/recruit/apply`

入力項目:
- 氏名
- フリガナ
- メールアドレス
- 電話番号
- 希望店舗
- 希望職種
- 希望雇用形態
- 勤務可能曜日・時間
- 志望理由
- 自由記入
- 履歴書添付
- 個人情報取り扱いへの同意

必須要件:
- Cloudflare Turnstile などのBot対策。
- サーバー側バリデーション。
- 個人情報利用目的の明示。
- 送信完了画面。
- 管理者への通知。

### 6.5 管理画面

パス候補:
- `/admin/recruitment`
- 別アプリの場合は `recruit-admin.landscapecoffee.jp` など。

画面:
- ダッシュボード
- 応募者一覧
- 応募者詳細
- 募集管理
- CSVインポート
- ユーザー・権限管理

## 10. 通知要件

初期:
- 新規応募時に採用担当へメール通知。
- CSVインポート完了時に管理者へ結果表示。

将来:
- Slack通知。
- 未対応応募のリマインド。
- 面接前日通知。
- ステータスが一定期間変わっていない応募者のアラート。

## 11. 外部媒体連携方針

### 11.1 Indeed

初期:
- 媒体名を `indeed` として手動登録またはCSV取り込み。
- 応募通知メールを受け取り、必要に応じて管理画面へ登録。

将来:
- Indeed Apply / ATS連携の可否を確認。
- 応募者情報をPOSTで受け取るエンドポイントを用意。
- 署名検証、重複判定、添付ファイル保存を実装。

### 11.2 スタンバイ

初期:
- 媒体名を `stanby` として手動登録またはCSV取り込み。
- 応募通知メール・CSVを運用で吸収。

将来:
- 公式APIまたはATS連携の提供有無を確認。
- 提供される場合のみ自動連携を追加。

### 11.3 公式サイト

最優先で実装する。応募フォームから直接DB保存するため、もっとも安定した応募経路になる。

## 12. 技術構成案

### 案A: 既存Astroサイト内に採用機能を追加

向いている場合:
- まずは小さく始めたい。
- 採用ページと応募フォームが主目的。
- 管理画面はシンプルでよい。

構成:
- Astro: 採用ページ、応募フォーム、簡易管理画面。
- Supabase: DB、認証、ファイル保存。
- Resend: 通知メール。
- Turnstile: Bot対策。

### 案B: 公式サイトと採用管理を分離

向いている場合:
- 応募者管理を長期的に育てたい。
- 権限、面接管理、通知、外部媒体連携を強くしたい。
- 管理画面のUIを作り込みたい。

構成:
- Astro: 採用ページ、応募フォーム。
- Next.js または別Astroアプリ: 採用管理画面。
- Supabase / Neon Postgres: DB。
- S3 / Supabase Storage: 添付ファイル。
- Resend: メール。
- Slack: 通知。

推奨:
- MVPは案Aで開始。
- 応募数や運用が増えたら管理画面を案Bへ分離できる設計にしておく。

## 13. セキュリティ・個人情報

必須:
- 応募者情報は公開サイト側に表示しない。
- 管理画面は認証必須。
- 店舗責任者の閲覧範囲を制限する。
- 履歴書ファイルは署名付きURLなどで限定公開する。
- 操作ログを保存する。
- 個人情報の利用目的を応募フォームに明記する。
- 一定期間後の削除または匿名化方針を決める。
- 秘匿情報は環境変数に置く。

検討:
- 個人情報保存期間。
- 不採用者データの保持期間。
- 応募者から削除依頼が来た場合の運用。
- 採用担当者退職時のアカウント停止フロー。

---

## 14. 成功条件

- 公式サイトから応募できる。
- どの媒体から来た応募者も同じ一覧で見られる。
- 新規応募に24時間以内に気づける。
- 応募者ごとに現在のステータス、次の対応、担当者が分かる。
- 店舗別・職種別に応募数が見える。
- 個人情報が適切に保護されている。

## 15. オープン課題

1. 採用ページを LANDSCAPE 公式サイト内に置くか、採用専用LPにするか。
2. 「オーブホームのホームページ」が別サイトを指す場合、そこからの応募導線をどう接続するか。
3. 応募通知の送信先メール。
4. 採用担当者・店舗責任者の人数と権限。
5. 履歴書添付を必須にするか、応募後提出にするか。
6. Indeed / スタンバイ側の契約・連携可否。
7. 個人情報の保存期間。
8. 採用管理画面を公式サイト内に置くか、別アプリにするか。
